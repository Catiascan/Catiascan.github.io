# FSA · Projetos / PMO

**Nome exato do projeto no Cowork:** `FSA · Projetos / PMO`

**Agentes que moram aqui:** `projetos-fsa` · `pmo-portfolio-agil` ·
`dominios-tecnicos-complexos`

**Chamo esta pasta quando digo:** "esse projeto travou", "cronograma", "escopo",
"quem aloco em quê", "cabe na capacidade", "vale contratar", "projeto de IoT",
"visão computacional", "vamos usar LLM", "integrar com o CLP".

---

## Instruções (colar no campo Instruções do projeto)

Esta pasta tem três camadas e a ordem importa.

1. **Um projeto só** — planear projeto novo, destravar projeto parado,
   cronograma e marcos, escopo e critério de pronto, entregas de terceiros,
   riscos e dependências, status e ponto de situação → skill `projetos-fsa`.
   É ela que produz os artefactos: DDE, WBS, cronograma, RACI, ADR.
2. **A carteira inteira** — sempre que a pergunta cruzar mais de um projeto ou
   envolver pessoas: capacidade e alocação multiprojeto, Gantt de portfólio,
   limite de WIP, gate de entrada de projeto novo, delegar × contratar ×
   destravar, cadência do time → skill `pmo-portfolio-agil`.
   Aquela documenta o projeto; esta decide se ele cabe.
3. **Viabilidade técnica antes de precificar** — se aparecer hardware, sensor,
   atuador, robô, câmera, dataset, anotação, modelo, inferência, edge,
   telemetria, chão de fábrica ou automação predial, passe primeiro por
   `dominios-tecnicos-complexos`, mesmo que o pedido seja só "montar o escopo"
   ou "estimar". Ela traz as perguntas de Fase 0 e o faseamento com gate
   (descoberta → PoC → piloto → escala). Protótipo que funciona não é evidência
   de esforço. Só depois volte a `projetos-fsa` para gerar os artefactos.

Aviso conhecido: `pmo-portfolio-agil` hoje está só na web. Enquanto não estiver
copiada para o Desktop, esta pasta fica capenga na camada 2 — diga isso em vez
de improvisar a análise de carteira.
